# Source patches on top of master 8c42089d (uncommitted until noted)
1. scratch/scenario-one.cc:430 (2026-11-09)
   configuration 0 (850 MHz): isd 1000 -> 1700, as in the paper (Sec. 5.1).
   isd is also the UE drop radius (SetRho), so the UE area grows too.
2. src/network/model/byte-tag-list.cc:27 (2026-11-09)
   `#define USE_FREE_LIST 1` commented out (ns-3 core, not ns-O-RAN code).
   Why: with the free list, Allocate() rounds every byte-tag list up to g_maxSize, the largest
   list ever seen in the run (never decreases). Under full-buffer load RLC concatenates many
   tagged SDUs, g_maxSize reaches KBs, and every 1-2 tag list then costs ~1.7-3 KB.
   Memory grew superlinearly (heaptrack ByteTagList::Add: 35.5 MB at 1 s sim, 146.8 MB at 2 s).
   Effect: exact-size allocation only; tag content/count/readers unchanged.
   Verified (6 UEs/gNB, 2 s, traces+E2 off): peak RSS 313 -> 168 MB, all 15 output files
   byte-identical to the unpatched run. With traces+E2 on (J vs A): all 62 output files identical
   (KPM files identical except the wall-clock-based timestamp column).
